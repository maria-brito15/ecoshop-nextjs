# Glossary (ubiquitous language)

Domain terms are English everywhere, including the contract (Prisma models, enum values, API keys; ADR-0023); the third column shows where each term appears.

| Term | Definition | Where it appears |
|---|---|---|
| User | A person with an account (unique email). Has a **type**. | `User` |
| Type / Role | `CUSTOMER`, `BRAND` or `ADMIN`. Defines what the user can do. | `UserType` |
| Brand | A company that makes catalog products; belongs to **exactly one** user (1:1). Not the same as the user. | `Brand` |
| Category | A grouping of products (e.g. Natural Cosmetics). | `Category` |
| Product | A catalog item: name, description, price, category, brand, photo, certificates. Not a purchase item. | `Product` |
| Certificate | A sustainability seal issued by a body (e.g. FSC). | `Certificate` |
| Photo | An image uploaded for a product, stored on disk (`public/data_photos`). Different from `photoUrl`. | `photo.service.ts` |
| EcoScan | The feature that identifies the material in a photo and explains its disposal. | `/ai-scan` |
| Material | The tag returned by the classifier (Azure) for a photo. | `tagName` |
| Confidence | Probability (0–100%) of the identified material. | `AI_CONFIDENCE_THRESHOLD` |
| Sustainability analysis | The 6 fields generated by Gemini: impact, decomposition, where to dispose, recyclability, tips, benefits. | `AiAnalysis` |
| Fallback | The static analysis used when Gemini fails or answers invalidly. | `fallbackAnalysis` |
| Living spec | A capability document with the behavior expected today. | `docs/capabilities` |
| REQ / BR / NFR | Requirement / business rule / non-functional requirement, with a stable ID. | specs |
